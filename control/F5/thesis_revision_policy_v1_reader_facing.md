# thesis_revision_policy_v1_reader_facing.md

## 1. 目的

本文件规定从当前中文完整草稿向俄文正式论文迁移时的正文修订纪律。核心原则是：论文必须让普通读者在不阅读项目治理文件、不查看 GitHub、不知道 run_id 的情况下，也能理解研究问题、模型、算法、实验与结论。

---

## 2. 正文禁止出现的内部词

### 2.1 项目治理词
正文禁止出现：
- F1, F2, F3, F4；
- freeze, rolling, final-freeze；
- contract, clean-lineage；
- project charter, model contract, result contract；
- experiment registry；
- gap closure。

这些词只服务内部项目管理，不属于学术论文正文。

### 2.2 技术标签
正文禁止出现：
- Main；
- d08；
- d04；
- run_id；
- `full__main__test__...` 等运行目录名；
- `summary_metrics.csv` 等文件名；
- Python 脚本路径。

### 2.3 推荐替代表达
| 内部词 | 正文表达 |
|---|---|
| Main | модель CtR–CtB / CtR–CtB 模型 |
| d08 | основная спецификация / 主规格 |
| d04 | более строгая спецификация ограничения CtB / 更严格 CtB 约束规格 |
| clean-lineage | расчеты, используемые в итоговом сравнении / 最终比较所用计算 |
| run_id | 只在附录复现说明中出现 |
| result contract | схема вывода результатов / 结果输出方案 |
| solver reliability protocol | проверка численной устойчивости / 数值稳定性检查 |

## 4. 公式与文字连贯性规则

### 4.1 公式出现前必须有动机
错误写法：
> 定义如下：公式。

推荐写法：
> 为了比较各资产对组合风险的贡献，需要先写出组合波动率对权重的边际变化。由此定义……

### 4.2 公式出现后必须有解释
每个核心公式后至少解释：
- 该公式衡量什么；
- 符号表示什么；
- 它在后续模型中承担什么作用。

### 4.3 不跳跃规则
不得从 Markowitz 直接跳到 CtR–CtB 模型。中间必须经过：
Markowitz/Tobin/Sharpe → 风险配置问题 → CtR → CtB → CtR–CtB。

---

## 5. 双目标解释的正文压缩规则

正文不需要长篇解释“为什么不用双均衡模型”，但必须保留最小解释。

推荐俄文表述：

> В работе не используется симметричная двухцелевая постановка, в которой CtR и CtB имеют одинаковый статус. Причина состоит в том, что CtR описывает распределение риска, а CtB описывает корреляционную структуру портфеля. Поэтому в основной модели CtR используется как главная цель, а CtB — как структурное ограничение.

中文含义：

> 本文不采用 CtR 与 CtB 地位完全相同的对称双目标模型。原因是 CtR 描述风险分配，而 CtB 描述组合相关结构。因此主模型中 CtR 是主目标，CtB 是结构约束。

## 6. 旧课程论文整合规则

旧课程论文只服务经典背景，不抢占主线。

### 6.1 正文保留
- Markowitz 模型；
- Tobin 模型；
- Sharpe 单指数模型；
- 经典模型局限。

### 6.2 附录可选
- 旧 t01.py listing；
- 旧课程论文中可复用的基础计算说明。

### 6.3 正文舍弃
- 旧 3.3.4 最优 k 数值实验；
- 旧股票实证结果；
- 旧三模型绩效图；
- 旧 t02.py 作为主程序证据。

理由：它们不属于当前 CtR–CtB 模型证据链。
